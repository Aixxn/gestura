# Gestura API Documentation

## Overview

The Gestura backend consists of two services exposing HTTP and WebSocket endpoints:

| Service | Base URL | Port | Purpose |
|---------|----------|------|---------|
| API Gateway | `http://<host>:8080` | 8080 | REST API (auth, translation proxy, health) |
| API Gateway (WS) | `ws://<host>:9898` | 9898 | Real-time translation results |
| Translation Service | `http://<host>:7860` | 7860 | Internal ML/segmentation (proxied via gateway) |

**Frontend should only interact with the API Gateway (port 8080/9898).** The Translation Service is internal and should not be exposed to clients.

---

## Authentication Endpoints

All auth endpoints are public (no token required). They are served by the API Gateway.

### `POST /api/auth/register`

Create a new user account.

**Request Body:**
```json
{
  "email": "user@example.com",
  "password": "securePassword123",
  "full_name": "Jane Doe"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `email` | string | Yes | Will be normalized to lowercase |
| `password` | string | Yes | Hashed with bcrypt (12 rounds) |
| `full_name` | string | No | Display name |

**Success Response (201):**
```json
{
  "success": true,
  "message": "Registration successful",
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "_id": "664f1a2b3c4d5e6f7a8b9c0d",
    "email": "user@example.com",
    "full_name": "Jane Doe",
    "created_at": "2024-01-01T00:00:00.000Z"
  }
}
```

**Error Responses:**
- `400` — Missing email or password
- `409` — Email already registered
- `500` — Server error

---

### `POST /api/auth/login`

Authenticate an existing user.

**Request Body:**
```json
{
  "email": "user@example.com",
  "password": "securePassword123"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `email` | string | Yes | Will be normalized to lowercase |
| `password` | string | Yes | Plaintext password for verification |

**Success Response (200):**
```json
{
  "success": true,
  "message": "Login successful",
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "_id": "664f1a2b3c4d5e6f7a8b9c0d",
    "email": "user@example.com",
    "full_name": "Jane Doe",
    "created_at": "2024-01-01T00:00:00.000Z"
  }
}
```

**Error Responses:**
- `400` — Missing email or password
- `401` — Invalid email or password
- `500` — Server error

**Token:** JWT with 7-day expiry. Include as `Authorization: Bearer <token>` in all protected requests.

---

### `POST /api/auth/logout`

Stateless logout (no-op on server). Frontend should discard the token.

**Success Response (200):**
```json
{
  "success": true,
  "message": "Logout successful"
}
```

### `GET /api/auth/me`

Get the currently authenticated user's profile. **Requires JWT.**

**Headers:**
```
Authorization: Bearer <token>
```

**Success Response (200):**
```json
{
  "success": true,
  "user": {
    "_id": "664f1a2b3c4d5e6f7a8b9c0d",
    "email": "user@example.com",
    "full_name": "Jane Doe",
    "created_at": "2024-01-01T00:00:00.000Z"
  }
}
```

**Error Responses:**
- `401` — No/malformed/expired token
- `404` — User not found
- `500` — Server error

## Translation Endpoints

Protected by JWT. Frontend sends camera frames here.

### `POST /api/convert`

Send a single camera frame for processing. **Requires JWT.**

**Headers:**
```
Authorization: Bearer <token>
```

**Request:** `multipart/form-data`

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `rawImage` | File (image/jpeg) | Yes | Camera frame as JPEG binary |
| `uuid` | string | Yes | Session UUID (generated by frontend) |

**Success Response (200):**

The response is proxied directly from the Translation Service. Possible statuses:

```json
{
  "status": "idle"
}
```
No hands detected (both hands absent for 15+ consecutive frames).

```json
{
  "status": "processing"
}
```
Frame received and being processed — no sign boundary detected yet.

```json
{
  "status": "word_detected",
  "word": "HELLO",
  "sign_index": 0
}
```
A complete sign was detected and classified.

**Note:** The `uuid` must be the same for the entire session. Generate it once when the camera screen mounts and reuse it for all frames. The same UUID is used for the WebSocket connection.

**Error Responses:**
- `400` — No file or UUID provided
- `401` — Invalid/expired JWT
- `500` — Translation service unavailable or processing error

---

### `GET /api/stop/:uuid`

Finalize a translation session and receive the full translation via WebSocket. **Requires JWT.**

**Headers:**
```
Authorization: Bearer <token>
```

**Path Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `uuid` | string | The session UUID to finalize |

**Success Responses:**
- `200` — `"Successfully finished sequence."` (session finalized successfully)

The actual translation result is pushed to the client **via the WebSocket connection** (see below).

**Error Responses:**
- `400` — No UUID provided
- `401` — Invalid/expired JWT
- `404` — No active session for this UUID
- `500` — Failed to process sequence

---

## WebSocket (Port 9898)

Used to receive real-time translation results pushed from the server.

### Connection

```
ws://<host>:9898?uuid=<session-uuid>&token=<jwt-token>
```

| Query Param | Required | Description |
|-------------|----------|-------------|
| `uuid` | Yes | Same session UUID used for `/api/convert` |
| `token` | Yes | JWT token for authentication |

### Message Format (Server → Client)

When a session is stopped via `GET /api/stop/:uuid`, the result is pushed through the WebSocket:

```json
{
  "type": "translation",
  "asl_gloss": "HELLO HOW ARE YOU",
  "english": "Hello, how are you?",
  "words": ["HELLO", "HOW", "ARE", "YOU"]
}
```

| Field | Type | Description |
|-------|------|-------------|
| `type` | string | Always `"translation"` |
| `asl_gloss` | string | Raw ASL gloss (space-separated detected words) |
| `english` | string | Grammar-corrected English sentence |
| `words` | string[] | Array of individually detected words |

### Reconnection

The WebSocket supports automatic reconnection with configurable retry (default: up to 5 attempts, 3-second interval). The connection is persistent for the entire session lifetime.

### Connection States

| State | Description |
|-------|-------------|
| Connected | Ready to receive translation results |
| Connecting | Initial handshake in progress |
| Disconnected | Connection lost — auto-reconnect will attempt recovery |
| Error | Authentication failure or network error |

## Internal Translation Service Endpoints

These endpoints are called by the API Gateway internally. **Do not expose to the frontend.** They are documented here for debugging and development.

### `POST /process-frame` (Translation Service)

Receive a decoded frame and run segmentation + ML inference.

**Request Body:**
```json
{
  "uuid": "session-uuid",
  "image_bytes": "<base64-encoded-image>",
  "timestamp_ms": 1704067200000
}
```

**Response:** Same as `/api/convert` response format.

### `POST /stop` (Translation Service)

Finalize session and run grammar correction.

**Request Body:**
```json
{
  "uuid": "session-uuid"
}
```

**Response:**
```json
{
  "asl_gloss": "HELLO HOW ARE YOU",
  "english": "Hello, how are you?",
  "words": ["HELLO", "HOW", "ARE", "YOU"],
  "success": true
}
```

### `POST /translate` (Translation Service)

Standalone ML inference on pre-normalized window (for debugging).

**Request Body:**
```json
{
  "window_data": [[0.1, 0.2, ...], ...]
}
```

**Response:**
```json
{
  "pred": "HELLO"
}
```

### `POST /convert-sentence` (Translation Service)

Standalone ASL gloss → English conversion via FLAN-T5 (for debugging).

**Request Body:**
```json
{
  "asl_gloss": "HELLO HOW ARE YOU"
}
```

**Response:**
```json
{
  "original": "HELLO HOW ARE YOU",
  "translated": "Hello, how are you?",
  "success": true,
  "error": null
}
```

### `GET /health` (Translation Service)

**Response:**
```json
{
  "status": "healthy",
  "service": "gesture-translation"
}
```

## Error Response Format

All API errors follow this structure:

```json
{
  "success": false,
  "message": "Human-readable error description"
}
```

In development mode, additional `stack` field may be included.

## Rate Limits / Timeouts

| Endpoint | Timeout | Notes |
|----------|---------|-------|
| `/api/convert` | 5000ms | Per-frame processing |
| `/api/stop/:uuid` | 15000ms | Includes FLAN-T5 inference |
| WebSocket reconnect | 3000ms interval | Max 5 attempts |
